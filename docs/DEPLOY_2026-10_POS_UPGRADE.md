# คู่มือ deploy รอบอัปเกรดหน้าขาย (ตุลาคม 2026)

รอบนี้รวมงานระยะ 1–3 ของการปรับปรุงหน้าขาย:
- PIN ผู้จัดการ, สินค้าระบุราคา, โหมดฝึกขาย
- เครื่องพิมพ์ USB, QR ใบเสร็จสำหรับลูกค้า, ขอใบกำกับภาษี
- PromptPay อัตโนมัติ (Opn / GB Prime Pay)
- ขายออฟไลน์ และเปิดหน้าขายใหม่ได้ขณะไม่มีเน็ต
- backend อัปเดตฐานข้อมูลเองตอนเริ่มทำงาน

ทำตามลำดับด้านล่างทีละข้อ ใช้เวลาประมาณ 30–45 นาที ควรทำนอกเวลาขาย

---

## 0. ก่อนเริ่ม
1. **สำรองฐานข้อมูล:** Plesk → Databases → ฐานข้อมูลของร้าน → **Export Dump** แล้วดาวน์โหลดเก็บไว้
2. ให้ทุกเครื่องที่หน้าขาย **ปิดกะ** ให้เรียบร้อย
   - ถ้ามีบิลออฟไลน์ค้าง (แถบ "รอส่ง N ใบ") ต้องให้ส่งเข้าระบบหมดก่อน

## 1. ฐานข้อมูล (อัตโนมัติแล้ว)
ตั้งแต่รอบนี้ **ไม่ต้อง import ไฟล์ migration ผ่าน phpMyAdmin อีก**
- ตอน backend เริ่มทำงาน ระบบจะรันไฟล์ใน `database/migrations` ที่ยังไม่ได้รันให้เองตามลำดับ
- รอบนี้คือ 016–024 เท่าที่ยังขาด
- ตัวอย่าง error ที่จะหายไป: "ฐานข้อมูลยังไม่ได้อัปเดต (ไม่พบ คอลัมน์ p.open_price)"

**เงื่อนไข:**
- deploy ด้วย **Git** จะมีโฟลเดอร์ `database/` อยู่ข้าง `backend/` อยู่แล้ว ไม่ต้องทำอะไรเพิ่ม
- ถ้าอัปโหลดด้วย **FTP/File Manager** ต้องอัปโหลด `database/migrations` ไปไว้ข้างโฟลเดอร์ `backend` ด้วย
  - หรือตั้ง `MIGRATIONS_DIR` ให้ชี้ไปที่โฟลเดอร์นั้น
- user ฐานข้อมูลต้องมีสิทธิ์ `ALTER` / `CREATE` ซึ่ง user ที่ Plesk สร้างให้มีอยู่แล้ว

**ตรวจผลหลังข้อ 2:** เปิด `https://<โดเมน backend>/api/health` แล้วดูส่วน `schema`:

| ค่าที่เห็น | ความหมาย |
|---|---|
| `"state": "done"` และ `"pending": []` | เรียบร้อย |
| `"state": "failed"` | ดู `error.migration` (ไฟล์ที่หยุด) และ `error.message` (สาเหตุ) แก้แล้วกด Restart App อีกครั้ง หรือ import ไฟล์นั้นเองผ่าน phpMyAdmin |
| `"state": "skipped"` | ไม่พบโฟลเดอร์ migrations (ดูเงื่อนไขด้านบน) |

> ถ้าต้องการ import เองเหมือนเดิม ให้ตั้ง `AUTO_MIGRATE=false`
> ไฟล์ที่เคย import ไปแล้วบางส่วน ระบบจะข้ามส่วนที่มีอยู่แล้วและทำส่วนที่เหลือต่อจนครบ

## 2. Backend (Plesk)
1. **ดึงโค้ด:** Websites & Domains → Git → **Pull Updates** (หรืออัปโหลดไฟล์ใหม่)
2. **Node.js → NPM install**
3. **Custom environment variables** — เพิ่มหรือตรวจค่าต่อไปนี้:

| ตัวแปร | ค่า | ใช้ทำอะไร |
|---|---|---|
| `APP_ENCRYPTION_KEY` | สุ่ม 32 ไบต์ base64 ด้วยคำสั่ง `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` | เข้ารหัสคีย์ผู้ให้บริการชำระเงิน **ตั้งครั้งเดียวแล้วห้ามเปลี่ยน** ถ้าเปลี่ยนต้องใส่คีย์ใหม่ทั้งหมด |
| `APP_PUBLIC_URL` | `https://<โดเมนหน้าเว็บบน Vercel>` | ลิงก์ QR บนใบเสร็จ และที่อยู่ webhook ของ GB Prime Pay |
| `PUBLIC_API_URL` *(ถ้ามี)* | `https://<โดเมน backend>` | ถ้าตั้งไว้ GB Prime Pay จะแจ้งเงินเข้าตรงที่ backend |
| `AUTO_MIGRATE` | `true` (ค่าเริ่มต้น ไม่ต้องใส่ก็ได้) | อัปเดตฐานข้อมูลเอง |

4. กด **Restart App**
5. ตรวจ `/api/health` ตามข้อ 1 และดูว่า `jobs` ไม่ฟ้องว่างานค้าง
   - งานค้างแปลว่า Scheduled Task ทุก 1 นาทียังไม่ทำงาน ให้ดูขั้นที่ 5 ใน `DEPLOY_PLESK.md`

## 3. Frontend (Vercel)
1. merge เข้า `main` แล้ว Vercel จะ deploy ให้เอง
   - เช็กว่าเวอร์ชันใหม่ขึ้นแล้วหรือยังได้จากเลขเวอร์ชันมุมล่างของเมนูซ้าย
2. ไม่มีตัวแปรใหม่ฝั่ง Vercel (`BACKEND_URL` เหมือนเดิม)
3. ให้ทุกเครื่องหน้าขาย **รีเฟรชหน้า /pos หนึ่งครั้งขณะออนไลน์**
   - ครั้งนี้เครื่องจะเก็บหน้าขายไว้ใช้ตอนเน็ตหลุด

## 4. ตั้งค่าในแอปหลัง deploy
**ผู้จัดการ / เจ้าของร้าน**
1. **ตั้ง PIN ผู้จัดการ:** ตั้งค่า → บัญชีของฉัน (`/settings/account`) → การ์ด **PIN ผู้จัดการ** (4–6 หลัก)
   - แคชเชียร์ใช้คืนสินค้า ยกเลิกบิล หรือให้ส่วนลดเกินสิทธิ์ได้เมื่อมีผู้จัดการกรอก PIN
2. **สินค้าระบุราคา:** ไปที่สินค้า → เพิ่มสินค้า → ติ๊ก "ระบุราคาตอนขาย ไม่นับสต๊อก"
   - ใช้กับของที่ไม่มีบาร์โค้ด เช่น ถ่ายเอกสาร หรือค่าบริการเติมเงิน
3. **หน้าขาย → ตั้งค่า:**
   - ใส่ LINE OA (ถ้ามี)
   - เลือกว่าจะออกใบกำกับภาษีเต็มรูปให้อัตโนมัติเมื่อลูกค้าขอผ่าน QR หรือให้ผู้จัดการกดออกเอง

**ทีละเครื่องที่หน้าขาย (ใช้ Chrome หรือ Edge)**

4. **เครื่องพิมพ์:** หน้าขาย → ปุ่ม **เครื่องพิมพ์** → **จับคู่ผ่าน USB** → เลือกเครื่อง
   - ตั้งขนาดกระดาษ 58 หรือ 80 มม.
   - กด **พิมพ์ทดสอบ** ต้องเห็นภาษาไทยครบทั้งสระและวรรณยุกต์
   - กด **เปิดลิ้นชักทดสอบ**
   - ถ้าเครื่องขึ้นเป็น COM port ให้ใช้ปุ่ม "เครื่องแบบ COM port"
   - บน Windows บางรุ่นต้องเปลี่ยนไดรเวอร์เป็น WinUSB ด้วย Zadig ก่อน (ถ้าจับคู่แล้วขึ้น access denied)

## 5. PromptPay อัตโนมัติ (ไม่บังคับ)
ร้านต้องสมัครกับผู้ให้บริการเองก่อน **ทดลองในโหมดทดสอบก่อนใช้จริงเสมอ**

หน้าขาย → ตั้งค่า → **รับชำระ PromptPay อัตโนมัติ**

### GB Prime Pay
1. เลือก **GB Prime Pay**
2. ใส่ **Token (Customer key)** และ **Secret key** จากหน้า Merchant ของ GB Prime Pay
3. ติ๊ก **โหมดทดสอบ (Sandbox)** ถ้าเป็นคีย์ของบัญชีทดสอบ
4. กด **บันทึก** แล้วกด **ทดสอบการเชื่อมต่อ**
5. ไม่ต้องตั้ง webhook เพราะระบบส่งที่อยู่แจ้งเงินเข้าไปพร้อม QR ทุกครั้ง
   - ต้องตั้ง `APP_PUBLIC_URL` หรือ `PUBLIC_API_URL` เป็น https ก่อน
   - ถ้าไม่ได้ตั้ง บิลก็ยังปิดเองได้ เพราะเครื่องจะถามสถานะทุก 2–3 วินาที

### Opn Payments (Omise)
1. ใส่ **Secret key** (`skey_test_…` = โหมดทดสอบ)
2. คัดลอก **URL แจ้งเงินเข้า (Webhook)** ไปใส่ใน Opn Dashboard → Webhooks

### ทั้งสองเจ้า
- ติ๊ก **เปิดใช้ที่หน้าขาย** → ลองขายยอดเล็กๆ (เช่น ฿20) ด้วย PromptPay
  - QR ต้องขึ้นและบิลต้องปิดเองเมื่อจ่าย
- เปลี่ยนไปใช้คีย์จริงหลังลองแล้วเท่านั้น
- เปลี่ยนคีย์ทีละช่องได้ ช่องที่เว้นว่างจะคงคีย์เดิมไว้
- **ข้อจำกัด:**
  - ทั้งสองเจ้ายังไม่เคยลองกับบัญชีจริง ถ้า QR ไม่ขึ้นหรือบิลไม่ปิดเองในโหมดทดสอบ ให้ส่งข้อความ error ที่เห็นมา
  - ค่าธรรมเนียมผู้ให้บริการยังไม่ถูกลงบัญชีอัตโนมัติ
  - การคืนเงินผ่านผู้ให้บริการต้องทำในหน้าเว็บของผู้ให้บริการเอง

## 6. เช็กลิสต์ทดสอบหลัง deploy (ลองที่หน้าร้านจริง)
- [ ] `/api/health` → `schema.state` = `done`
- [ ] เปิดกะ → สแกนสินค้า → รับเงินสด → ทอนถูก → ใบเสร็จพิมพ์ออกเครื่องพิมพ์ (หรือหน้าพิมพ์ของเบราว์เซอร์)
- [ ] ขายสินค้าระบุราคา (ปุ่ม **ระบุราคา**)
- [ ] แคชเชียร์กดคืนสินค้า → ขอ PIN ผู้จัดการ → คืนได้
- [ ] สแกน QR บนใบเสร็จด้วยมือถือ → เปิดหน้าใบเสร็จได้ → ลองขอใบกำกับภาษี
- [ ] ค้นหาบิลย้อนหลังด้วยยอดเงินหรือเบอร์โทรในปุ่ม **บิล / คืนของ**
- [ ] **ออฟไลน์:** ถอดสาย LAN หรือปิด Wi-Fi → แถบ "ออฟไลน์" ขึ้น → ขายเงินสด 1 บิล → กดรีเฟรชหน้าขณะยังออฟไลน์ หน้าขายต้องเปิดได้ → ต่อเน็ตกลับ → บิลถูกส่งเข้าระบบเอง (แถบ "รอส่ง" หายไป)
- [ ] ปิดกะ → ยอดเงินสดตรง → พิมพ์สรุปปิดกะ
- [ ] (ถ้าเปิด PromptPay อัตโนมัติ) ขาย ฿20 ในโหมดทดสอบ → บิลปิดเอง
- [ ] โหมดฝึกขาย (ในการ์ดแนะนำ) ขายแล้วไม่มีบิลจริงเกิดขึ้น

## 7. ข้อควรรู้เรื่องโหมดออฟไลน์
- ขายได้เฉพาะ **เงินสด** ราคาป้าย ไม่มีโปรโมชั่น ส่วนลด หรือแต้ม
  - ใบเสร็จที่ได้เป็น "ใบเสร็จชั่วคราว" ส่วนเลขบิลจริงจะได้เมื่อส่งเข้าระบบ
- เปิดหน้าใหม่ขณะออฟไลน์ได้เฉพาะ **หน้าขาย** และเฉพาะเครื่องที่เคยเปิดหน้าขายตอนออนไลน์มาแล้ว หน้าอื่นต้องมีเน็ต
- ปิดกะไม่ได้จนกว่าบิลออฟไลน์จะส่งครบ
- อย่าล้างข้อมูลเบราว์เซอร์ (Clear browsing data) ขณะมีบิลค้างส่ง เพราะบิลเก็บอยู่ในเครื่อง
- ออกจากระบบแล้ว เครื่องจะลืมข้อมูลผู้ใช้และกะ (บิลค้างส่งยังอยู่)

## 8. ถ้ามีปัญหา — ย้อนกลับ
- **PromptPay อัตโนมัติมีปัญหา:** เอาติ๊ก "เปิดใช้ที่หน้าขาย" ออก หน้าขายจะกลับไปใช้ QR ธรรมดาและการตรวจสลิปแบบเดิม
- **หน้าเว็บมีปัญหา:** Vercel → Deployments → เลือกเวอร์ชันก่อนหน้า → **Promote to Production**
- **backend มีปัญหา:** Git → เลือก commit ก่อนหน้า → Deploy → Restart App
- **ฐานข้อมูล:** migration ทุกไฟล์ **เพิ่มอย่างเดียว** (คอลัมน์/ตารางใหม่) โค้ดเวอร์ชันเก่ายังใช้ได้ จึงไม่ต้องถอยฐานข้อมูล
  - ถ้าจำเป็นจริง ให้ใช้ไฟล์ที่ Export ไว้ในข้อ 0 (ข้อมูลหลังจากนั้นจะหาย)
